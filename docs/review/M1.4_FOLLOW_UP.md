# M1.4 Follow-up Review

**Date:** 2026-10-08
**Status:** In progress; not verified

This follow-up re-reviewed the M1.4 changes in `crates/nexus-tools/src/exec.rs` and its tests against the four priority issues identified in the [architecture review](ARCHITECTURE_REVIEW.md). It is a static re-review; it does not replace the original whole-workspace assessment or establish a security guarantee.

| Priority issue | Follow-up result | Remaining concern |
| --- | --- | --- |
| Fair, cancellation-responsive pipe draining | **Partially addressed.** Each stream has a 64 KiB drain quantum, and a regression fixture covers a continuously readable source. | `Interrupted` reads retry inside the drain helper without consuming the quantum, so a persistent interruption can still prevent cancellation/deadline checks. |
| Child/pipe ownership and runtime quarantine | **Partially addressed.** Exec cleanup retains the tool worker instead of returning while inherited output pipes remain open; runtime can quarantine that worker after cancellation/deadline. | The post-grace drain loop ignores cancellation and read errors. A persistent read error can keep the worker alive forever; failure to set nonblocking mode can enter a potentially blocking drain. Cleanup ownership is not yet expressed as a single resource guard. |
| Startup probe cleanup | **Partially addressed.** Probe runs in its own process group, has a 2-second deadline, and handles `try_wait` errors and timeout without immediately dropping the child. | Unconfirmed probe children are handed to detached reaper threads with no cap or retained join ownership. Repeated failures could accumulate threads; wait/error saturation is not covered by injected tests. |
| EOF descriptors and poll loop | **Addressed in the reviewed path.** EOF streams are excluded from polling, both-EOF waits sleep briefly, and non-interruption poll errors enter cleanup. | Platform-specific execution behavior still needs validation on Linux. |

The implementation's recorded validation is `cargo nextest run -p nexus-tools --locked --offline` (44 tests), formatting, and clippy. This does not cover Linux sandbox execution or injected wait/read/probe failures. The descendant-held-pipe regression is macOS-only. **M1.4 remains In progress, not Verified.** In particular, process-group signaling and pipe closure do not prove that a detached descendant which closed inherited descriptors has terminated.
